# E-001: does the genome a mind expresses change what its proposals found?

Status: **pre-registered 2026-10-28, before any arm served a request.** Arms, seeds and the
analysis script are committed below before the relay is switched on. Changes after that date
go in an "Amendments" section with the reason, never by editing the plan.

## Question

Kannaka's genome (kannaka-dna) claims that `chr3-mind`, `chr4-brain` and `temperament` are
heritable traits of how she thinks. When eight genomes that differ only in those genes serve as
the mind of a thegrid colony, does the fossil record tell them apart?

thegrid's own finding is that model-authored mutation founds nothing (Matt Eckman's fleet:
4,554 proposals, zero lineages). Our colony-one is different: 3,884 of 25,292 scorable
proposals since 2026-09-05 reached a positive tier (15.4%). The question is whether any genome
moves that number.

## Setting

- **Colony:** kannaka-grid `colony-one` on Skywave (an older thegrid, starvation economy,
  613 of 614 epochs extinct). One colony, so this is a within-colony comparison with the arms
  interleaved in time, not a replicated one.
- **Mind:** the Odin relay (`grid.odin`) asks a language model for one variant of the parent
  genome per request, at roughly 380 requests a day.
- **Evaluator:** `grid.verdicts`, nightly. Each proposal is joined to the fossil record by its
  genome id and given a tier from births and generations. This evaluator existed before the
  experiment and is not changed by it.

## Arms

Eight genomes, generated by `experiments/e001_make_arms.py` from the founder `kannaka-g0`
(`b9802c03…`) by mitosis at mutation rate 1.0 (every mutable gene mutates), seeds drawn from a
quantum random source (job id recorded in each genome's `conception`), then filtered:

- the brain allele must be one the gateway serves: `kannaka-brain-v1`, `-v2`, `-v3`,
  `kannaka-brain-7b-v1`. The founder's own allele, `kannaka-brain-7b-v2`, is **not served** and
  is excluded from this round. That is a limit of the deployment, and is stated here so it is
  not read as a result.
- the eight phenotypes (`model_alias`, `temperature`, `recall_top_k`) must be distinct.

Each genome is expressed as `role-swarm-mind`. The phenotype parameters are:

| parameter | gene | mapping |
|---|---|---|
| `model_alias` | `chr4-brain:brain` | repo name without `-GGUF` |
| `temperature` | `chr1-identity:temperament.playfulness` | `0.4 + 0.6 × playfulness` (0.58 to 0.88) |
| `recall_top_k` | `chr3-mind:recall-top-k` | as written (3 to 10) |
| `max_tokens` | none | fixed at 400 |

Nothing else about the ask changes: the prompt template is the registry default for every arm,
and recall is on for every arm. Conserved genes are identical across arms by construction.

## Assignment

The relay gains a `genome` dimension. Each request is assigned to an arm by a salted hash of
its request id with equal weights (`assign(request_id, dimension="genome", …)`), the same
mechanism the existing model and prompt arms use. So:
- arms are interleaved request by request, and every arm sees the same epochs and the same
  colony states;
- a deferred and retried request lands on the same arm;
- the model A/B dimension is disabled while the genome dimension runs (the relay refuses to
  start with both), so a request's model comes from its genome and nowhere else.

The arm is written into every proposal-log row (`genome`, `genome_hash`) and carried into every
verdict row.

## Measures

For each arm, over its settled verdicts with `outcome == "proposed"` and tier not in
`{preexisting, unknown, rejected}` (the exclusions `grid.weekly` already uses):

- **Primary:** positive rate = share of tiers in `{reproduced, growing, enduring, established}`.
- **Secondary:** mean fitness (births); validity = proposed ÷ (proposed + rejected) per arm;
  unborn rate.
- **Blind baseline, same epochs:** for the epochs the run spans, the share of blind-origin
  children (`transitions` rows whose child has no proposal-log row) with `births >= 2` in
  `genome_stats`. This is the number the arms have to beat to mean anything.

## Sample size and duration

Historical volume is ~380 proposals/day, about 72% of which are scorable. Over 8 arms that is
~34 scorable per arm per day. **The run is 14 days**, giving ~480 scorable verdicts per arm.
At a base rate of 15%, that detects a 7-point difference between one arm and the pooled rest
with about 80% power at α = 0.01. Smaller effects will read as null, and the null is a result.
There is no stopping for success. An interim look at day 7 checks only for harm (an arm whose
validity is under 50%), which would pause that arm and be logged as an amendment.

## Decision rules, fixed in advance

1. **Omnibus:** a permutation test (10,000 shuffles of arm labels over the scorable rows) on the
   spread of positive rates across the 8 arms. H0 is rejected at p < 0.01.
2. **If H0 is rejected:** the best arm is compared with the pooled others (two-sided
   permutation, α = 0.01). The two best arms mate with consent (`kdna mate`) and the child joins
   a second round with the founder's current best as the control. That round gets its own
   pre-registration.
3. **If H0 is not rejected:** stop. Report that `chr3-mind`, `chr4-brain` and `temperament`,
   over the ranges the genome allows, do not change what this colony's record selects. Do not
   widen the ranges and re-run without a new pre-registration.
4. **Blind baseline:** reported beside the arms in every outcome. If no arm beats the blind
   rate, that is the headline, whatever the omnibus says.

## What would make me reconsider the design

- Fewer than 200 scorable verdicts in any arm at day 14 (relay outages, gateway downtime).
  Then the run extends until every arm has 200, and the extension is logged.
- The colony goes extinct and restarts from the ancestral palette mid-run (its median epoch is
  short). Epoch boundaries are recorded per row; the analysis also reports per-epoch rates, so
  a run that straddles an extinction is readable rather than discarded.
- Any sign the arms are not interleaved (a chi-square on arm counts per day, p < 0.01).

## Confounds I know about

- **The colony changes over time.** Handled by per-request interleaving, not by per-epoch
  assignment.
- **The gateway serves four models at different speeds.** A slow model defers more requests
  and loses some to the bin. Deferred-and-binned rows are excluded from the positive rate but
  counted in validity, so a slow arm shows as low validity, not as low fitness.
- **The evaluator is itself a selection pressure on nothing but these proposals.** Blind births
  are not scored by the same code; the blind baseline is computed from the fossil tables
  directly, so the two numbers are comparable in definition (births ≥ 2) but not in pipeline.
- **One colony.** thegrid's rule is "never run one of anything you intend to learn from." This
  run cannot replicate across colonies. It can only interleave within one, and it says so.

## Analysis

`experiments/e001_analyze.py` (committed with this plan) reads `verdicts.jsonl`,
`proposals.jsonl` and `history.sqlite3` read-only and prints the table above plus the two
permutation tests. The script is frozen at the pre-registration commit; the run's result is
whatever it prints on day 14.

## Amendments

quantum draw. On the night of switch-on the OpenQuantum Rigetti harvest (70 min) and IQM Garnet
